# Introducing the new Python autograder (beta)

We're excited to announce a public beta of the new Python autograder for PrairieLearn: [`pytest-prairielearn-grader`](https://github.com/PrairieLearn/grader-python-v2). It's a ground-up rewrite built on [pytest](https://pytest.org/), and it ships with a set of features that support reliable graders and give students clear, actionable feedback.

## Why a new autograder?

The new autograder offers instructors a few key capabilities:

- **Security isolation.** Student code runs in a separate process as an unprivileged user, protecting the grading harness and keeping grading behavior reliable.
- **Clear feedback.** Students see short, readable messages by default, and built-in assertions explain what was checked without exposing the grader's internals.
- **Partial credit across inputs.** A test can check many inputs and give credit for each one that passes.
- **Plot grading.** Compare a student's matplotlib plot with a reference plot, and show the plot alongside the results.
- **Centralized configuration.** Timeouts, import restrictions, and other settings can be managed cleanly with `ConfigObject`.
- **Lightweight startup image.** Intro questions can use the `:lite` image (about a 50 MB download) for quick cold starts and a compact dependency surface.

## Key advantages for instructors

### Sandboxed execution

Student code runs in a separate process, isolated from the grader harness. This gives instructors reliable grading behavior with clear boundaries around imports, runtime behavior, and timeout enforcement. Modules such as `os`, `sys` and `subprocess` are blocked by default, and you can control exactly which modules students are allowed to import:

```python
# tests/test_student.py
from pytest_prairielearn_grader import ConfigObject

# Only these modules can be imported by student code
autograder_config = ConfigObject(import_whitelist=["math", "statistics"])
```

Each call to a student function has a time limit. If a call times out, the rest of that test is skipped, so an infinite loop or an inefficient solution can't use up the grading job's time.

### Student-friendly feedback

By default, students see only a clean, structured message, with no Python traceback from the grader:

```
Checking: add(2, 3)
Expected output: 5
Your code output: -1
The expected and actual output do not match.
```

This comes from the built-in assertion helpers (`assert_fn_equal`, `assert_equal`, etc.), which generate these messages automatically. If the student's own function raises an error, the message includes the traceback from their code, so they can see where it went wrong. For more advanced courses, you can show the full traceback with `@pytest.mark.output(level="traceback")` on a test.

### Partial credit across many inputs

To check a function on many inputs and give credit for each one that passes, use pytest's built-in `subtests`:

```python
@pytest.mark.grading_data(name="Check random values", points=3)
def test_random_values(sandbox: StudentFixture, subtests: pytest.Subtests) -> None:
    for n in [2, 3, 5, 8, 13, 17, 19, 23, 27, 29]:
        with subtests.test():
            assert_fn_equal(sandbox, "fib", args=(n,), expected=fib(n))
```

The test gets the fraction of inputs that passed, and students see a summary such as `7/10 checks passed.` followed by the first few failures. If the student's function times out, the remaining inputs are skipped and the message says why.

### Grading plots

Student code draws a plot with matplotlib as usual, and the test compares it with a reference plot. `assert_plot_equal` checks the axis scales and the data in each line, scatter plot and bar plot, and `feedback.add_image` shows the student's plot with their results:

```python
@pytest.mark.grading_data(name="plot", points=1)
def test_plot(sandbox: StudentFixture, feedback: FeedbackFixture) -> None:
    plot = sandbox.query("plot")
    if isinstance(plot, Figure):
        feedback.add_image(plot, label="Your plot")
    assert_plot_equal(plot, reference_plot())
```

### Automatic ungradable detection

If a student submits code with a `SyntaxError`, the grader marks the submission as **ungradable**. PrairieLearn's external grading framework then allows students to fix and resubmit without consuming a grading attempt, while still showing a clear error message. This is especially helpful in courses where students are still learning Python syntax.

### A lightweight image for intro courses

Two Docker images are published:

| Image | Download size | Includes |
|-------|---------------|----------|
| `prairielearn/grader-python-pytest:latest` | ~270 MB | Full scientific stack: numpy, pandas, scipy, matplotlib, sympy, scikit-learn, and more |
| `prairielearn/grader-python-pytest:lite` | ~50 MB | Grader core only, with no scientific libraries |

For introductory CS courses where students use only the Python standard library, the `:lite` image is the right choice. Its lightweight footprint supports quick cold-start pulls and a reduced security surface.

## A simple intro-course example

Here's what a complete question setup looks like for an intro CS course using the `:lite` image.

### `info.json`

```json
{
  "title": "Implement add()",
  "topic": "Functions",
  "tags": ["intro", "functions"],
  "type": "v3",
  "gradingMethod": "External",
  "externalGradingOptions": {
    "enabled": true,
    "image": "prairielearn/grader-python-pytest:lite",
    "timeout": 30
  }
}
```

### `question.html`

```html
<pl-question-panel>
  <p>
    Write a function <code>add(a, b)</code> that returns the sum of two numbers.
  </p>
</pl-question-panel>

<pl-file-editor file-name="student_code.py" ace-mode="ace/mode/python">
def add(a, b):
    # your code here
    pass
</pl-file-editor>
```

### `tests/test_student.py`

```python
import pytest
from pytest_prairielearn_grader.assertions import assert_fn_equal
from pytest_prairielearn_grader.fixture import StudentFixture


@pytest.mark.grading_data(name="add(2, 3) returns 5", points=3)
def test_add_basic(sandbox: StudentFixture) -> None:
    assert_fn_equal(sandbox, "add", args=(2, 3), expected=5)


@pytest.mark.grading_data(name="add(-1, 1) returns 0", points=3)
def test_add_negative(sandbox: StudentFixture) -> None:
    assert_fn_equal(sandbox, "add", args=(-1, 1), expected=0)


@pytest.mark.grading_data(name="add(0, 0) returns 0", points=4)
def test_add_zeros(sandbox: StudentFixture) -> None:
    assert_fn_equal(sandbox, "add", args=(0, 0), expected=0)
```

When a student submits `return a - b` by mistake, they see:

```
Checking: add(2, 3)
Expected output: 5
Your code output: -1
The expected and actual output do not match.
```

Students get concise, actionable feedback focused on what to fix next.
